# IXseal — IXcloud 계정정보 봉인 전달 서비스 설계서 (v0.3)

> 저장소: `kinx12399/IXseal` · 단일 VM에 배포 · UI 설계는 [UI.md](UI.md), 시안은 [mockup/index.html](mockup/index.html)

## 1. 배경과 목표

현재 고객 요청(VM 생성, 계정 생성 등)으로 만든 계정정보를 **메일 본문에 평문으로** 보내고 있다. 그래서 메일함·전달·백업에 비밀번호가 영구히 남는다.

**목표**: 엔지니어가 계정정보(텍스트·파일)를 이 서비스에 등록하고 열람 링크를 받는다. 고객에게는 그 링크만 전달하고, 고객은 링크에 접속해 계정정보를 확인한다. 정해진 시간이 지나거나 폐기 조건을 충족하면 내용은 삭제된다.

| 범위 안 (v1) | 범위 밖 (v1) |
| --- | --- |
| 엔지니어 화면에서 등록 → 링크 복사 (메일 발송은 엔지니어가 기존 방식대로) | 메일·SMS 자동 발송 (§9 확장 지점만 둔다) |
| 텍스트 필드 + 파일 첨부(.pem, .key, .zip 등) | 포털/티켓 시스템 연동 |
| 링크만으로 열람 (별도 인증 없음) | 고객 2차 인증 |
| 만료 시간 지정, 1회 열람 폐기, 고객 확인 폐기 | 엔지니어 개인 로그인 (보안그룹 IP 제한으로 대체) |

### 수용한 위험

1. **링크만으로 열람할 수 있다.** 메일이 유출되면 만료 전까지는 내용도 유출된다. 다음 장치로 위험을 줄인다.
   - 만료 시간을 짧게 둔다(기본 24시간).
   - 1회 열람 폐기와 고객 확인 폐기를 둔다.
   - 열람 기록(시각·IP)을 남긴다.
   - 고객에게 비밀번호 변경을 권고한다.
2. **엔지니어 화면은 사무실 IP(1.201.194.31)만 허용하고 개인 로그인은 없다.** 사무실 네트워크 안의 누구나 등록·회수할 수 있다. 다만 **등록한 내용은 엔지니어 화면에서 다시 볼 수 없으므로**(§8), 내부자가 계정정보를 열람할 경로는 없다.

## 2. 전체 흐름

```text
[엔지니어 @ 사무실 1.201.194.31]
   │ https://seal.ixcloud.net:8443/
   │ 등록: 템플릿 선택 → 고객명, 제목, 섹션별 항목, 파일, 만료 시간, 폐기 방식 (고객 화면 미리보기)
   ▼
[서비스] ① 필드·파일을 암호화해 저장 (DB에는 암호문만)
         ② 토큰 생성 → DB에는 토큰의 SHA-256만 저장
         ③ 화면에 링크를 1회만 표시: [링크 복사] [메일 문구 복사]
   │
   │ 엔지니어가 기존 메일에 링크를 붙여 고객에게 보냄
   ▼
[고객] https://seal.ixcloud.net/s/<토큰>
   ├ GET  → 안내 화면: 제목, 만료 시각, 폐기 방식 안내, [계정정보 보기]
   ├ POST → 필드 표시, 파일 다운로드, (설정 시) [확인 완료 · 폐기]
   └ 열람 기록 → 엔지니어 화면의 상태가 '열람됨'으로 바뀜
   ▼
만료 / 1회 열람 / 고객 확인 / 엔지니어 회수 → 암호문 삭제, 링크는 "만료됨" 화면
```

**GET과 POST를 분리하는 이유**: 메일 보안 스캐너(Outlook Safe Links 등)와 메신저 미리보기는 링크를 자동으로 연다. GET에서는 내용도 보여주지 않고 열람으로 세지도 않아야, 1회 열람 링크가 스캐너 때문에 소진되지 않는다.

## 3. 열람·폐기 정책

엔지니어가 등록할 때 두 가지를 고른다.

**만료 시간** (필수): 1시간 / 6시간 / **24시간(기본)** / 3일 / 7일. 최대는 7일이다.

**폐기 방식** (택1):

| 방식 | 동작 |
| --- | --- |
| **기간 내 무제한** (기본) | 만료 전까지 몇 번이든 열람할 수 있다. 횟수는 기록만 한다. |
| **1회 열람 후 폐기** | [계정정보 보기]를 누른 순간 폐기 처리한다. 그 화면에서 파일을 받을 수 있도록 10분짜리 열람 세션을 준다(아래 참고). |
| **고객 확인 시 폐기** | 무제한으로 열람할 수 있고, 열람 화면에 [확인 완료 · 지금 폐기] 버튼을 표시한다. 고객이 누르면 즉시 폐기한다(확인 대화상자 표시). |

- 어떤 방식이든 만료 시간이 지나면 폐기한다. 엔지니어는 언제든 [회수]할 수 있다.
- **열람 세션**: POST로 열람할 때 HttpOnly·Secure·SameSite=Strict 쿠키로 10분짜리 세션을 발급한다. 파일 다운로드(`GET /s/{token}/files/{id}`)는 이 세션이 있어야만 허용한다. 따라서 링크만으로는 파일을 직접 받을 수 없고, 반드시 [보기]를 거쳐야 한다.
- 1회 열람 방식에서는 POST 시점에 DB 상태를 `consumed`로 바꾼다. 텍스트는 이미 응답에 담았고, 파일 암호문은 세션이 끝나거나 모든 파일을 받은 뒤 삭제한다. 동시 요청은 `UPDATE ... WHERE status='active' RETURNING`으로 막아 한 번만 성공하게 한다.

상태 전이:

```text
active ──열람(무제한/확인형)──▶ active (view_count++)
active ──열람(1회형)──────────▶ consumed ──세션 종료──▶ purged
active ──고객 확인 클릭───────▶ purged
active ──만료 / 엔지니어 회수──▶ purged
```

## 4. 시스템 구성

```text
                      ┌──────────── ixcloud VM ────────────┐
Internet ─ 443  ─────▶│ Nginx :443  (공개)                  │
 (보안그룹 전체 허용)   │   /s/*  → public 앱 (127.0.0.1:8001) │
                      │   그 외 → 404                       │
사무실 1.201.194.31 ─ 8443 ─▶│ Nginx :8443 (관리)                 │
 (보안그룹 사무실만)    │   /*    → admin 앱  (127.0.0.1:8002) │
사무실 ─ 22 (SSH)  ───▶│                                     │
                      │ FastAPI ×2 (같은 코드, 진입점 분리)   │
                      │ PostgreSQL (localhost 전용)          │
                      │ 마스터키 /etc/ixseal/kek (0440)     │
                      └─────────────────────────────────────┘
```

- **포트로 관리 화면을 분리한다**: 보안그룹은 경로(`/admin`)가 아니라 포트 단위로 제한한다. 그래서 공개용 443과 관리용 8443을 나누고, 8443은 보안그룹에서 `1.201.194.31/32`만 허용한다. Nginx나 앱에 IP 제한을 따로 두지 않는다.
- **앱 분리**: 공개 앱에는 관리 라우트 자체가 없다. 443으로 들어온 요청은 관리 기능에 닿을 수 없다. 이는 보안 설정이 아니라 구조로 생기는 분리다.
- **도메인**: 운영 시 `seal.ixcloud.net`을 쓴다(IXcloud 콘솔 `console.ixcloud.net`과 같은 도메인 계열). 443과 8443에 같은 인증서를 쓴다.
- **개발 단계 TLS**: 와일드카드 인증서(`*.ixcloud.net`)는 운영 전환 시 요청한다. 개발 중에는 VM 공인 IP로 접속하고, 다음 중 하나를 쓴다.
  - **자체 서명 인증서** (기본): 추가 포트가 필요 없다. 브라우저 경고는 개발 중에만 감수한다.
  - **Let's Encrypt IP 인증서**: 경고가 없지만, 80 포트를 외부 전체에 열어야 하고 약 6일마다 자동 갱신해야 한다.
  - 인증서 경로는 설정 파일 하나로 관리한다. 운영 전환은 인증서 교체와 `server_name` 변경만으로 끝나게 한다.
- **보안그룹 요약**: 443 전체 허용 / 8443·22는 `1.201.194.31/32`만 허용 / 80은 인증서 발급 방식에 따라 결정(§12).

## 5. 암호화

- 시크릿마다 무작위 DEK(256bit)를 만든다. 필드 JSON과 각 파일을 **AES-256-GCM**으로 암호화하며, 파일마다 nonce를 따로 쓴다.
- DEK는 KEK로 감싸서 저장한다. KEK는 DB가 아니라 VM 파일에 둔다. 키를 교체할 때는 `kek_id`로 신·구 키를 구분한다.
- GCM의 AAD로 `secret_id`(파일은 `secret_id`+`file_id`)를 넣어 암호문을 바꿔치기하지 못하게 한다.
- **폐기 = 암호문·DEK를 지운다**(`payload`·`dek_wrapped`를 NULL로, 파일 행은 DELETE). 메타데이터는 감사용으로 남긴다(§10).
- 한계: 폐기 전에 만든 DB 백업(최대 7일 보관)과 PostgreSQL의 옛 행 버전(autovacuum 전)에는 암호문과 감싼 DEK가 남아 있어, **KEK가 함께 있으면 복호화할 수 있다.** 그래서 KEK를 DB·백업과 분리해 보관하는 것이 핵심이다(DEPLOY.md §3).
- DB 백업에는 암호문만 담기며, KEK는 백업과 따로 보관한다.

## 6. 링크 토큰

- 32바이트 CSPRNG 값을 base64url로 인코딩한 43자 토큰을 쓴다. DB에는 `SHA-256(token)`만 저장한다.
- 원문 토큰은 **등록 직후 화면에 한 번만** 보여준다. 엔지니어가 링크를 잃어버리면 [재발급](새 토큰을 만들고 기존 토큰은 폐기)한다.
- Nginx에서 `/s/*`에 IP당 요청 제한을 걸어 토큰 대입 공격을 막는다. 토큰 형식이 틀리거나 일치하는 것이 없으면 모두 같은 "유효하지 않은 링크" 화면을 보여준다.

## 7. 파일 첨부

형식은 넓게 허용하되, **서버와 고객 브라우저 어디에서도 실행·렌더링되지 않게** 한다.

| 항목 | 정책 |
| --- | --- |
| 허용 | 확장자 제한 없음이 기본이다(.pem, .key, .ppk, .crt, .ovpn, .zip, .7z, .txt, .csv, .pdf 등). |
| 차단 | 실행 파일과 스크립트를 막는다. ① 확장자: `.exe .msi .bat .cmd .com .scr .ps1 .vbs .js .jse .wsf .hta .lnk .jar .sh .bin .run .app .dmg .apk .dll .so` ② **매직바이트**: PE(`MZ`), ELF(`\x7fELF`), Mach-O. 확장자를 바꾼 실행 파일도 막는다. |
| 크기 | 파일당 20MB, 시크릿당 최대 10개·총 50MB (Nginx `client_max_body_size`와 일치시킴) |
| 저장 | 암호화한 뒤 PostgreSQL `bytea`에 저장한다. 웹 경로와 디스크 파일이 없으므로 서버에서 실행될 가능성이 없다. |
| 처리 | 서버는 파일을 **열거나 해석하지 않는다.** 압축 해제, 미리보기, 썸네일 모두 없다. |
| 다운로드 | `Content-Type: application/octet-stream` 고정, `Content-Disposition: attachment; filename*=UTF-8''…`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`. HTML이나 SVG도 브라우저가 렌더링하지 않고 내려받기만 한다. |
| 파일명 | 경로 구분자와 제어문자를 제거하고 200바이트로 자른다. 파일명도 내용과 함께 암호화해 저장한다. |
| 위치 | 템플릿의 **파일 항목**(예: VM의 "키 파일")에 연결한 파일은 그 섹션 안에, 연결하지 않은 파일은 맨 아래 "첨부 파일"에 보인다. 같은 파일을 여러 항목에 연결할 수 있다(VM 여러 대가 같은 키 사용). |

- 압축 파일 안의 실행 파일은 검사하지 않는다. 암호화된 zip은 검사할 수도 없다. 엔지니어가 직접 올리는 파일이라 신뢰하는 것으로 보고, 백신 검사(ClamAV)는 v2 후보로 둔다.

## 8. 화면

### 고객 (공개, 443)
| 경로 | 내용 |
| --- | --- |
| `GET /s/{token}` | 제목, 고객명, 만료 시각, 폐기 방식 안내 문구, [계정정보 보기] |
| `POST /s/{token}/reveal` | 섹션별 항목(값 가리기·보기·복사, URL은 새 창 열기), 섹션 안내문, 파일 목록·다운로드, (확인형) [확인 완료 · 지금 폐기] |
| `GET /s/{token}/files/{id}` | 열람 세션이 있을 때만 다운로드 |
| `POST /s/{token}/destroy` | 고객 확인 폐기 (열람 세션 필요) |

공통 응답 헤더:
- `Cache-Control: no-store`
- `X-Robots-Tag: noindex`
- `Referrer-Policy: no-referrer`
- 엄격한 CSP (외부 리소스 없음)
- HSTS

모든 고객 화면(안내·열람·만료) 하단에 **"문의사항은 Cloud 헬프데스크(help_cloud@kinx.net)로 메일 보내 주세요."**를 표시한다. 주소는 설정값 `HELPDESK_EMAIL`로 관리한다. 엔지니어 화면의 메일 안내문에도 같은 문장을 넣는다.

### 엔지니어 (관리, 8443)
- **목록**: 상태(대기 / 열람됨 / 폐기됨 / 만료 / 회수), 고객명·제목·담당자 검색, 남은 시간
- **등록**: 템플릿 선택 → 기본 정보(고객명, 제목, 요청 번호, 담당자) → 템플릿 섹션 입력(반복 섹션은 [VM 추가]) → 파일 → 열람 기한·폐기 방식. 오른쪽에 **고객 화면 실시간 미리보기**를 둔다(§8.1).
- **등록 완료**: 링크를 한 번만 표시한다. [링크 복사], [메일 문구 복사](고객명, 링크, 만료 시각, 폐기 방식을 넣은 안내문)
- **상세**: 상태, 열람 기록(시각·IP·UA), [회수], [재발급]
- **템플릿 목록·편집**: §8.1
- 등록한 뒤에는 **엔지니어 화면에서도 내용을 볼 수 없다.**

## 8.1 템플릿과 미리보기

엔지니어가 템플릿을 자유롭게 만들고, 고치고, 복제할 수 있다. 템플릿은 "어떤 항목을 어떤 순서로, 어떤 안내와 함께 보여줄지"만 정의하고, **비밀 값은 담지 않는다.**

### 구조

```text
템플릿
├─ 이름, 설명, 기본 제목, 기본 열람 기한, 기본 폐기 방식
└─ 섹션 [순서 있음]
   ├─ 제목 (예: "IXcloud 콘솔 계정", "VM 접속 정보")
   ├─ 반복 여부 + 단위 (예: 반복 · "VM" → 등록 시 [VM 추가]로 여러 대 입력)
   ├─ 항목 [순서 있음]: 이름, 유형(텍스트 / 비밀(가림) / URL / 여러 줄 / 파일), 기본값, 필수 여부
   └─ 안내문 [순서 있음]: 톤(안내 / 주의), 본문
```

- 반복 섹션은 첫 항목(예: VM 이름)의 값을 고객 화면 소제목으로 쓴다: "VM 1 · web-01".
- 비밀 유형 항목에는 기본값을 저장할 수 없다(UI에서 비활성, 서버에서도 거부).
- 안내문은 **일반 텍스트**만 받는다. 고객 화면에서 이스케이프한 뒤 `http(s)://` URL과 메일 주소만 링크로 바꾼다(HTML 입력 불가, XSS 방지). URL 유형 항목도 `http(s)://`로 시작할 때만 [새 창 열기] 버튼을 붙인다.
- 제한: 섹션 10개, 섹션당 항목 30개, 안내문 1,000자.

### 기본 템플릿 (초기 데이터)

| 템플릿 | 섹션 | 기본값 |
| --- | --- | --- |
| **신규 계정 + VM** | ① IXcloud 콘솔 계정(콘솔 주소 `https://console.ixcloud.net`, 아이디, 초기 비밀번호 + 비밀번호 변경 안내) ② VM 접속 정보 (반복·VM: VM 이름, 접속 주소, SSH 포트 22, 계정 root, **키 파일** + **보안그룹 SSH 허용 안내** + 키 파일 보관·접속 방법 안내) | 24시간 · 확인 후 폐기 |
| VM 접속 정보 | VM 접속 정보 (반복·VM, 키 파일) + 보안그룹 안내 + 키 파일 안내 | 24시간 · 확인 후 폐기 |

VM은 비밀번호가 아니라 **키 파일로 접속**하므로 VM 섹션에는 비밀번호 항목이 없다.
| IXcloud 콘솔 계정 | 콘솔 계정 + 비밀번호 변경 안내 | 24시간 · 확인 후 폐기 |
| DB 계정 | 호스트, 포트 3306, DB 이름(선택), 계정, 비밀번호 | 6시간 · 1회 열람 |
| 빈 양식 | 항목 1개 | 24시간 · 기간 내 무제한 |

보안그룹 안내문 (신규 계정 + VM):
> VM에 접속하려면 먼저 위 콘솔 계정으로 IXcloud 콘솔(https://console.ixcloud.net)에 로그인한 뒤, 해당 VM의 보안그룹에서 접속하실 곳의 IP에 SSH(22) 포트를 허용해 주세요.

### 템플릿과 전달의 관계

- 전달을 만들 때 템플릿 구조를 **복사(스냅샷)**해서 값과 함께 암호화한다. 템플릿을 나중에 고치거나 지워도 이미 보낸 전달의 화면은 바뀌지 않는다.
- 등록 화면에서는 템플릿을 고른 뒤에도 항목 추가·삭제, 가림 전환, 안내문 수정을 그 전달에 한해 할 수 있다.
- 템플릿 삭제는 보관(`archived_at`) 처리한다. 목록에서만 숨긴다.
- 템플릿을 저장·삭제하면 `access_logs`에 기록한다(`template_saved`, `template_archived`, actor=`admin:<담당자명>`).

### 고객 화면 미리보기

- 새 전달 화면과 템플릿 편집 화면 오른쪽에 휴대폰 크기의 미리보기를 둔다. [안내 | 열람] 화면을 전환할 수 있고, 입력할 때마다 반영된다.
- **같은 Jinja 템플릿으로 렌더링한다**: 관리 앱이 `POST /api/preview`(입력 중인 JSON)를 받으면, 고객 화면과 같은 매크로(`templates/customer/_macros.html`)와 같은 뷰 모델(`views.py`)로 HTML 조각을 만들어 돌려준다. 관리 화면은 이 조각을 미리보기 틀에 넣는다(입력 후 250ms 디바운스). 서버가 모든 값을 이스케이프하므로 그대로 넣어도 안전하고, 미리보기와 실제 고객 화면이 어긋날 일이 없다. (iframe은 CSP 상속 문제로 쓰지 않는다.)
- 미리보기 요청은 저장하지 않고 로그에도 값을 남기지 않는다. 관리 포트(8443)에서만 받는다.
- 비어 있는 항목은 미리보기에서만 "등록 시 입력", "아직 입력하지 않음"으로 표시하고, 실제 고객 화면에서는 숨긴다.

## 9. 알림 확장 지점 (v1은 구현하지 않음)

이벤트 발행 인터페이스만 정의한다. v1의 구현체는 `NullNotifier`로 아무것도 하지 않는다.

```python
class Notifier(Protocol):
    def on_event(self, event: SecretEvent) -> None: ...
# SecretEvent: created | revealed | consumed | destroyed_by_customer | expired | revoked
```

이후 `SmtpNotifier`(고객 메일 자동 발송, 열람 시 엔지니어 알림)나 `SlackNotifier`, `SmsNotifier`를 설정으로 붙인다. 고객 메일 자동 발송에 대비해 `recipient_emails` 컬럼은 미리 두되, v1에서는 선택 입력이다.

## 10. 데이터 모델 (PostgreSQL)

스키마 원본: [ixseal/migrations/001_init.sql](../ixseal/migrations/001_init.sql). 마이그레이션은 번호 붙은 SQL 파일을 `python -m ixseal migrate`가 한 번씩 적용한다(`schema_migrations` 테이블로 추적).

| 테이블 | 내용 |
| --- | --- |
| `secrets` | 전달 1건. 메타데이터(제목·고객·담당자·템플릿 이름·방식·상태·기한·열람 수)는 평문, 내용은 `payload`(AES-GCM 암호문)와 `dek_wrapped`(KEK로 감싼 DEK). 상태 `active → consumed(1회 열람, 파일만 남음) → purged` |
| `secret_files` | 파일 1개 = 행 1개. `blob` = AES-GCM(DEK, 파일명‖내용). 폐기 시 행 삭제 |
| `reveal_sessions` | [보기] 후 10분짜리 세션 (파일 받기·고객 폐기에 필요). 토큰 해시만 저장 |
| `templates` | 템플릿 (평문 JSON, 비밀 값 없음). 삭제는 `archived_at` |
| `access_logs` | 등록·링크 확인·열람·파일 받기·폐기·회수·재발급·만료·템플릿 저장 기록 (IP, UA) |

암호문 형식은 모두 `nonce(12바이트) ‖ ciphertext+tag`이다. AAD는 `secret_id`(파일은 `secret_id ‖ file_id`)이다.

`secrets.payload`를 복호화한 내용 (템플릿 스냅샷 + 값):

```json
{ "v": 1,
  "files": [ { "id": "…uuid…", "name": "gaon-keypair.pem", "size": 1704 } ],
  "sections": [
  { "title": "IXcloud 콘솔 계정", "repeat": false,
    "instances": [[ { "label": "콘솔 주소", "type": "url", "value": "https://console.ixcloud.net" },
                    { "label": "아이디", "type": "text", "value": "admin@example.com" },
                    { "label": "초기 비밀번호", "type": "secret", "value": "…" } ]],
    "notices": [ { "tone": "warn", "text": "처음 로그인한 뒤 비밀번호를 변경해 주세요." } ] },
  { "title": "VM 접속 정보", "repeat": true, "unit": "VM",
    "instances": [ [ { "label": "VM 이름", "type": "text", "value": "web-01" }, …,
                     { "label": "키 파일", "type": "file", "value": "gaon-keypair.pem", "file_id": "…uuid…" } ],
                   [ …db-01 (같은 file_id 가능)… ] ],
    "notices": [ { "tone": "info", "text": "VM에 접속하려면 …" } ] }
]}
```

## 11. 보존 기간 (법적 요건 검토)

| 데이터 | 보존 | 근거 |
| --- | --- | --- |
| 계정정보·파일 (암호문, DEK) | **만료·폐기 즉시 삭제** (삭제 작업 5분 주기) | 개인정보보호법 제21조: 보유기간 경과·목적 달성 시 지체 없이 파기 |

- ⚠️ 이 판단은 2차 자료를 근거로 했다. 운영 전에 사내 정보보호/법무 담당 또는 ISMS-P 기준으로 확인받아야 한다.

## 16. 기술 구성

- Python 3.12+, FastAPI, Jinja2 서버 렌더링 (SPA 없음). 고객 화면 JS는 보기·복사·카운트다운만, 관리 화면 JS는 입력 폼·템플릿 편집기·미리보기를 맡는다.
- PostgreSQL 16+, psycopg 3 (+ psycopg-pool), 번호 붙은 SQL 마이그레이션 (`python -m ixseal migrate`)
- 암호화: `cryptography` (AESGCM)
- 폰트(Pretendard, OFL)·아이콘·CSS·JS를 모두 VM에서 직접 제공한다(외부 CDN 없음, CSP `default-src 'self'`, inline script·style 없음).
- 관리 API의 CSRF 방어: 상태를 바꾸는 요청은 `X-IXseal: 1` 헤더가 있어야 한다(다른 사이트의 폼·스크립트는 이 헤더를 붙여 보낼 수 없다).
- systemd 유닛: `ixseal-public`, `ixseal-admin`, `ixseal-maintenance.timer`(5분), `ixseal-backup.timer`(매일 03:30)
- 테스트: `pytest` 45개 (단위 28 · PostgreSQL 흐름 17). 배포 방법은 [DEPLOY.md](DEPLOY.md).
